# 🚀 Pull Request 작성 스킬 (`write-pr`)

**트리거:** `/write-pr`

`CONTRIBUTING.md`에 명시된 PR 템플릿 규격에 맞춰 현재 브랜치의 커밋 및 변경 파일 내역을 분석하고 표준 Pull Request 제목과 본문을 작성합니다.

---

## 📌 사용법

```text
/write-pr [주차 또는 추가 설명]
```

**예시:**
- `/write-pr`
- `/write-pr Week02 2주차 미니 웹페이지 제작 PR 작성`

---

## 📋 표준 PR 템플릿 규격

```markdown
[Week ##] 설명

## 📌 개요
간단 설명

## 🛠️ 주요 변경 사항

### 1. <이모지> 설명 `파일명`
- [] 한 일들

## 🔍 검증 및 확인 사항
- [] 한 일들
```

---

## ⚙️ 실행 절차 (Workflow)

### 1단계: 브랜치 및 변경 이력 분석
1. 현재 브랜치 이름과 기준 브랜치(`main`) 간의 차이를 확인합니다:
   ```bash
   git branch --show-current
   git log main..HEAD --oneline
   git diff --stat main..HEAD
   ```
2. 현재 브랜치명에서 주차 번호(예: `Week02`, `Week2` -> `[Week 02]`)를 파악합니다.
3. 어떤 파일들이 추가/수정되었는지, 각 커밋의 핵심 작업이 무엇인지 파악합니다.

### 2단계: PR 본문 구성 (템플릿 채우기)
1. **제목**: `[Week ##] 핵심 작업 요약` 형식으로 작성합니다. (예: `[Week 02] 2주차 미니 웹페이지 및 소개 페이지 제작`)
2. **📌 개요**: 이번 작업의 목적과 배경을 1~2줄로 명확하게 요약합니다.
3. **🛠️ 주요 변경 사항**:
   - 변경된 주요 파일별로 이모지와 함께 소제목을 구성합니다. (예: `### 1. ✨ 미니 웹페이지 추가 `hello.html``, `### 2. 📝 가이드 문서 갱신 `CONTRIBUTING.md``)
   - 각 파일에서 수행한 구체적인 작업들을 체크박스(`- [x]`) 목록으로 작성합니다.
4. **🔍 검증 및 확인 사항**:
   - 로컬 테스트, 브라우저 화면 검증, 링크 작동 여부, 컨벤션 준수 여부 등을 체크리스트로 작성합니다.

### 3단계: PR 텍스트 출력 및 생성 옵션 제공
- 완성된 마크다운 전문을 사용자에게 코드 블록 형태로 깔끔하게 제시합니다.
- `gh` CLI(GitHub CLI)가 설치되어 있는 경우 PR 자동 생성 명령어를 안내하거나 바로 실행할 수 있도록 지원합니다:
  ```bash
  gh pr create --title "[Week ##] 제목" --body "..."
  ```
- 웹 브라우저 GitHub 페이지에서 직접 복사하여 붙여넣을 수 있도록 마크다운을 제공합니다.

### 4단계: 점검 및 결과 보고
- 주차 번호 추출, 템플릿 섹션(개요/변경사항/검증) 반영 여부, `main..HEAD` 커밋 누락 여부를 점검하고, 결과를 상태 아이콘(🟢 정상 / 🟡 확인 필요 / 🔴 실패)과 함께 보고합니다.
  - 예: 🟢 `[Week 02] ...` PR 본문 작성 완료 / 🟡 브라우저 확인은 사용자가 직접 진행 필요
