# 📝 커밋 스킬 (`commit`)

**트리거:** `/commit`

`CONTRIBUTING.md`에 명시된 커밋 규칙에 따라 현재 변경사항(`git status`, `git diff`)을 분석하여 표준 커밋 메시지를 작성하고 커밋을 수행합니다.

---

## 📌 사용법

```text
/commit [선택적 추가 설명 또는 특정 파일]
```

**예시:**
- `/commit`
- `/commit hello.html 다크모드 추가 작업 커밋해줘`

---

## 📐 커밋 메시지 규칙 (`CONTRIBUTING.md` 기준)

### 1. 기본 구조
```text
<Type>: <Subject>
```

### 2. 커밋 타입 (Types)
| Type | 설명 | 사용 예시 |
| :--- | :--- | :--- |
| **`feat`** | 새로운 기능 추가 | `feat: 자기소개 페이지 방명록 기능 추가` |
| **`fix`** | 버그 및 오류 수정 | `fix: 모바일 화면에서 모달 레이아웃 깨짐 현상 수정` |
| **`docs`** | 문서 추가 및 수정 | `docs: CONTRIBUTING.md PR 템플릿 추가` |
| **`style`** | 코드 스타일/디자인 변경 (로직 영향 X) | `style: 메인 컬러 팔레트 및 버튼 여백 조정` |
| **`refactor`** | 코드 리팩토링 (기능 변경 X) | `refactor: 이벤트 리스너 핸들러 모듈화` |
| **`chore`** | 설정 파일, 빌드, 패키지, 잡무 | `chore: .gitignore 규칙 업데이트` |

### 3. 세부 작성 지침
1. **최대한 간결한 개조식 문장**: `~추가`, `~수정`, `~삭제`, `~개선` 등 간결한 명사형/명령조로 작성합니다.
2. **마침표 생략**: 제목(Subject) 끝에는 마침표(`.`)를 붙이지 않습니다.
3. **타입 소문자 유지**: `feat:`, `fix:`, `docs:`와 같이 접두어는 항상 소문자로 작성합니다.
4. **논리적 분리**: 여러 성격의 변경사항이 섞여 있는 경우, 변경사항별로 나누어 스테이징하고 개별 커밋하는 것을 권장합니다.

---

## ⚙️ 실행 절차 (Workflow)

### 1단계: Git 상태 및 변경사항 분석
1. 변경 파일 및 스테이징 상태를 확인합니다:
   ```bash
   git status
   git diff --staged
   git diff
   ```
2. 어떤 파일들이 추가/수정/삭제되었는지 파악하고 주된 목적(기능, 버그, 문서, 스타일 등)을 식별합니다.

### 2단계: 최적의 커밋 메시지 생성
- 변경 내용에 가장 적절한 `<Type>`을 선택합니다.
- 핵심 변경 내용을 50자 내외의 명확한 한국어 개조식 문장으로 요약합니다.
- 여러 작업이 혼합된 경우, 논리적 단위로 분리 커밋할지 사용자에게 제안하거나 순차 커밋합니다.

### 3단계: 스테이징 및 커밋 실행
1. 대상 파일을 스테이징합니다:
   ```bash
   git add <파일경로>  # 또는 git add .
   ```
2. 생성된 컨벤션 메시지로 커밋을 실행합니다:
   ```bash
   git commit -m "<Type>: <Subject>"
   ```

### 4단계: 점검 및 결과 보고
- 변경사항 분리 여부, 타입 일치 여부, 컨벤션 준수 여부를 점검하고, 커밋 해시와 메시지를 상태 아이콘(🟢 정상 / 🟡 확인 필요 / 🔴 실패)과 함께 보고합니다.
  - 예: 🟢 `feat: 방명록 실시간 작성 기능 추가` 커밋 완료 (`a1b2c3d`) / 🟡 문서 수정과 기능 추가가 한 커밋에 혼재되어 분리 권장
- 다음 작업(푸시 또는 `/write-pr` 등)을 안내합니다.
