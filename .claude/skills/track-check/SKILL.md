# 🧭 트랙 판정 스킬 (`track-check`)

**트리거:** `/track-check`, "판정표", "트랙 판정", "이 아이디어 바이브/엔지니어링 판정해줘"

주어진 아이디어를 4주차 기준으로 검토해, 트랙1(바이브코딩)로 가볍게 만들지 트랙2(엔지니어링)로 신중하게 만들지 판정표 형식으로 보고합니다.

---

## 📌 사용법

```text
/track-check [아이디어 한 줄 설명]
```

**예시:**
- `/track-check 감정일기 페이지에 달력과 분석 그래프 추가하기`
- `이 아이디어 판정표로 봐줘: 회원 결제 내역 대시보드`

아이디어가 이미 저장소에 존재하는 페이지/기능을 확장하는 것이라면, 판정 전에 관련 파일(예: `feel.html`, `expense.html` 등)을 실제로 읽어 현재 구조(백엔드 유무, 저장 방식, 공개 배포 여부 등)를 확인한 뒤 판정 근거로 삼습니다. 추측으로 판정하지 않습니다.

---

## 🧪 판정 절차 (Workflow)

### 1단계: 5조건 판정 (잘 먹히는 조건)
아래 5가지 조건 각각을 O/X로 판정하고, 근거를 한 줄씩 답니다.
- **낮은 위험**: 실패해도 피해가 작은가 (데이터 유실 정도 vs 금전/신뢰 손실)
- **작은 규모**: 기존 코드에 국소적으로 얹는 수준인가, 새 시스템/백엔드가 필요한가
- **짧은 수명**: 장기 유지보수·호환성 부담이 없는 1회성/학습용인가
- **제한된 사용자**: 본인 또는 소수만 쓰는가, 불특정 다수가 쓰는가
- **빠른 피드백**: 브라우저 새로고침 등으로 즉시 확인 가능한가

### 2단계: 프로덕션행 여부 판정
위 조건들을 바탕으로 이 코드가 "프로덕션(실서비스, 타인이 실제로 쓰는 배포본)"으로 가는 것인지 YES/NO로 판정하고 이유를 한 줄로 답니다.

### 3단계: 배포 전 체크리스트 5문
아래 5문항 각각을 YES/NO로 판정하고 근거를 답니다. 하나라도 YES면 그 항목에 해당하는 최소 안전장치(예: XSS 이스케이프, 시크릿 미노출, 되돌리기 확인 절차 등)를 결론에서 함께 언급합니다.
1. **외부접근**: 불특정 다수가 접근 가능한 곳에 배포되는가
2. **금융**: 금전/결제/거래 정보를 다루는가
3. **개인정보**: 개인 식별 정보나 민감한 개인 데이터를 다루는가
4. **위험동작**: 삭제·전송 등 되돌리기 어려운 동작이 있는가
5. **시크릿**: API 키 등 자격증명을 다루는가

### 4단계: 최종 결론
5조건과 체크리스트 결과를 종합해 **트랙1(바이브코딩)** 또는 **트랙2(엔지니어링)**을 권고하고, 이유를 한 줄로 답니다. 체크리스트에서 YES가 나온 항목이 있다면 트랙1을 유지하더라도 지켜야 할 최소 안전장치를 함께 명시합니다.

## 📋 출력 형식

```text
## 판정표

**아이디어:** <한 줄>

**5조건**
| 조건 | 판정 | 이유 |
|---|---|---|
| 낮은 위험 | O/X | ... |
| 작은 규모 | O/X | ... |
| 짧은 수명 | O/X | ... |
| 제한된 사용자 | O/X | ... |
| 빠른 피드백 | O/X | ... |

**② 프로덕션행인가? → YES/NO**
이유 한 줄

**③ 배포 전 체크리스트 5문**
| 문항 | 판정 | 근거 |
|---|---|---|
| ① 외부접근 | YES/NO | ... |
| ② 금융 | YES/NO | ... |
| ③ 개인정보 | YES/NO | ... |
| ④ 위험동작 | YES/NO | ... |
| ⑤ 시크릿 | YES/NO | ... |

**④ 최종 결론: 트랙1(바이브코딩) / 트랙2(엔지니어링)**
이유 한 줄 (+ 체크리스트 YES 항목에 대한 최소 안전장치 언급)
```

이 스킬은 판정·보고만 수행하며, 사용자 승인 없이 코드를 임의로 수정하지 않습니다.
