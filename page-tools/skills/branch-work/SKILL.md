# 🌿 주차별 브랜치 작업 스킬 (`branch-work`)

**트리거:** `/branch-work`

주차별 브랜치(`Week##`, 예: `Week02`, `Week03` 등)를 생성/체크아웃하고 해당 브랜치에서 요청받은 작업을 수행합니다.

---

## 📌 사용법

```text
/branch-work <주차 또는 브랜치명> <작업 요구사항>
```

**예시:**
- `/branch-work Week02 2주차 미니 웹페이지 제작 및 hello.html 수정`
- `/branch-work Week03 기능 1개 추가 및 page-checker 검증`
- `/branch-work 2주차 과제 체크리스트 완료하기`

---

## ⚙️ 실행 절차 (Workflow)

### 1단계: 브랜치명 판별 및 검사
1. 사용자의 입력에서 주차 정보(예: `2주차` -> `Week02`, `Week2` -> `Week02`, `Week03` 등) 또는 명시된 브랜치명을 추출합니다.
   - 주차 표기는 두 자리 숫자 포맷인 `Week02`, `Week03` 등을 기본 권장형식으로 사용합니다.
   - 특정 기능명이 명시된 경우 `Week##-<feature>` 형태도 가능합니다.
2. 현재 Git 상태를 확인합니다:
   ```bash
   git status
   git branch
   ```
3. 작업 트리가 깨끗하지 않다면 사용자에게 알리거나 적절히 처리한 후 진행합니다.

### 2단계: 기준 브랜치 확인 및 대상 브랜치 생성/전환
1. 기본적으로 최신 `main` 브랜치를 기준으로 분기합니다:
   ```bash
   # 브랜치가 이미 존재하는 경우
   git checkout <브랜치명>
   
   # 브랜치가 없는 경우 (main 기준으로 생성)
   git checkout main
   git pull origin main  # 원격 연동 시
   git checkout -b <브랜치명>
   ```
2. 현재 활성화된 브랜치가 `<브랜치명>`인지 확인합니다.

### 3단계: 작업 수행 (Plan → Execute → Verify)
1. **Plan (계획)**: 사용자 요구사항을 분석하고 수정/생성할 파일 목록을 도출합니다.
2. **Execute (실행)**: 해당 브랜치에서 필요한 코드 작성, 파일 추가, 디자인 개선 등의 작업을 수행합니다.
3. **Verify (검증)**: 브라우저 확인, 파일 내용 검증, 린트/에러 확인 등을 통해 작업 완결성을 점검합니다.

### 4단계: 작업 결과 및 검증 안내
- 완료된 작업 내역과 변경된 파일 목록을 간결하게 요약해 보고합니다.
- **실행 / 검증**: 결과물을 직접 확인할 수 있는 여는 법 1줄과 손으로 확인할 체크포인트 1~3가지를 함께 제공합니다.
- 다음 단계로 커밋 스킬(`/commit`) 또는 PR 작성 스킬(`/write-pr`)을 호출할 수 있도록 안내합니다.
