# repo-grade: AI-Ready 저장소 채점 스킬

이 스킬은 현재 저장소가 **AI 에이전트(Agent)가 일하기 좋은 상태(AI-Ready)**인지 객관적인 루브릭에 따라 100점 만점으로 채점하고, 적은 노력으로 큰 점수 상승을 얻을 수 있는 ROI 기반 개선 제안을 제공합니다.

## 1. 평가 절차
1. **실제 파일 검증**: 저장소 내 핵심 파일(`CLAUDE.md`, `README.md`, `package.json`, `tests/`, `src/` 등)을 직접 열어 실제 상태를 확인합니다. 추측으로 점수를 매기지 않습니다.
2. **카테고리별 채점**: 아래 5개 카테고리(각 20점 만점) 루브릭에 따라 0점, 10점, 20점을 판정합니다.
3. **결과 및 ROI 도출**: "카테고리 | 점수 | 근거 | 개선 제안" 표를 작성하고, 총점 및 노력 대비 효과가 큰 상위 3가지 개선 과제를 도출합니다.

---

## 2. 평가 루브릭 (5개 카테고리 × 각 20점 = 총 100점)

| 카테고리 | 0점 기준 | 10점 기준 | 20점 기준 |
| :--- | :--- | :--- | :--- |
| **(A) 길 안내**<br>(진입점·핵심 파일 안내) | 진입점이나 핵심 파일/디렉토리 구조 안내가 전혀 없음 | README 등에 일부 안내가 있으나 불완전하거나 구조 파악이 어려움 | 주요 진입점, 핵심 파일 및 디렉토리 구조가 명확히 문서화되어 있어 에이전트가 즉시 탐색 가능 |
| **(B) 규칙 문서 품질**<br>(CLAUDE.md 간결성 & 필수 항목) | 규칙 문서가 없거나 100줄 이상으로 너무 길어 컨텍스트를 과도하게 소모함 | 규칙 문서가 있으나 35줄을 초과하거나, 핵심 명령어 또는 금지사항 중 일부가 누락됨 | `CLAUDE.md`가 35줄 이내로 간결하며, 핵심 명령어(`npm test` 등)와 명확한 금지사항(Do & Don't)을 모두 포함함 |
| **(C) 숨은 규칙 문서화**<br>(Why·Gotcha 기록) | 프로젝트 고유의 주의사항(Gotcha)이나 기술적 결정 이유(Why)가 전혀 기록되어 있지 않음 | 일반적인 설명은 있으나 함정(Gotcha)이나 비직관적 규칙의 이유(Why)가 부분적으로만 기록됨 | 실수하기 쉬운 함정(Gotcha)과 이유(Why)가 명확히 문서화되어 에이전트의 반복 실수를 방지함 |
| **(D) 검증 게이트**<br>(테스트 및 npm test 실행성) | 테스트 코드가 없거나 실행할 수 없음 | 테스트 코드가 일부 존재하나 `npm test` 명령어로 정상 실행되지 않거나 실패함 | 핵심 로직에 대한 테스트가 갖춰져 있고 `npm test` 명령어로 한 번에 정상 검증 가능함 |
| **(E) 신선도**<br>(문서와 최근 코드 일치) | 문서와 실제 코드베이스 간 불일치가 심하여 에이전트에게 잘못된 판단을 유도함 | 대다수 내용은 일치하나 일부 삭제/변경된 코드나 경로가 문서에 방치되어 있음 | 문서에 적힌 경로, 명령어, 규칙이 현재 코드 및 환경과 정확히 일치함 |
